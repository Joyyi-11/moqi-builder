# `[对齐]` 工作流

精确触发 `[对齐]` 表示{{USER_NAME}}要求回看本轮协作，判断哪些变化值得跨会话保留，并在确认后写入唯一真实源、验证、创建本地 commit。普通的「同步」「更新文档」不触发本工作流。

## 一、识别：AI 提议

AI 先回看本轮对话与磁盘状态，产出一份**候选清单**，不直接改文件。

- 候选只从本轮实际发生的交互里找，不从记忆、印象或推测里补。
- 每条候选写明：**内容**、**建议写入位置**、**理由**（为什么它会改变以后的行为或判断）。
- 候选可以是一条措辞修正，也可以是一次结构变更；不以数量论价值，也不为凑数提议。

**四条判据（命中任一即可提议）**

1. **跨会话复现**：同类问题出现不止一次，或下次很可能再遇到。
2. **改变判断或行动**：知道它以后，AI 的选择会不同。
3. **现有规则失效**：旧规则互相冲突、已经过期，或反复没被遵守。
4. **稳定偏好或事实变化**：用户明确表达过，且不是一次性情绪。

**排除项**：一次性操作过程、临时情绪与推测、已有规则覆盖的内容、只对一个项目成立却想上移的经验——先落项目，等第二个项目复发再上移。

## 二、确认：用户逐条决定

- 每条候选由用户给出：**采纳 / 改写后采纳 / 拒绝 / 暂缓**。
- 未获明确确认的内容不写入；沉默、讨论、追问、评价都不构成确认。
- AI 可以补充理由、反例和取舍建议，但最终决定权归用户。
- 写入范围以当次确认为界；范围扩大时重新确认，不顺手扩展。

## 三、分流：落到哪个唯一真实源

| 信息类型 | 唯一写入位置 |
|:---------|:-------------|
| 每轮必须执行的行为、红线和路由 | `entrypoints/AGENTS.md` |
| 平台独有的加载方式和差异 | 对应平台薄适配器 |
| 会改变当前协作判断的事实和资料源 | `self/Memory.md` |
| 多个场景支撑的稳定思维模式 | `self/Soul.md` |
| 有明确任务触发条件的低频细则 | 对应 `references/*.md` |
| 系统维护、信息分流和清理机制 | `ALIGNMENT.md` |
| 一次性过程、操作流水、未验证信息 | 不写入 |

## 四、改写而非追加

- 先改唯一真实源，再检查适配器、路由、链接和校验器是否需要联动。
- 优先改写、合并和删除，最后才新增；不把更新理解为只追加规则。
- 同一规则只保留一个真实源；入口原则和领域步骤不逐句复制。
- 删除过期状态、失效路径、相对时间和不再影响判断的事实。
- 写入前核对新增或改写与现有条目是否矛盾：有矛盾先提出，并列出处与处置建议，不静默并存。
- `Soul.md` 不根据单一事件形成稳定结论。
- reference 只有在确有重复任务场景且入口存在路由时才保留。

### Gotcha 的退出条件

Gotcha 必须写清发生了什么、已确认的原因、以后必须怎样做。

主入口不设 Gotcha 段；按领域写入对应 reference，项目独有的写入该项目 `AGENTS.md`。

- 只记录真实发生、影响严重或重复出现且尚未解决的问题；活跃 Gotchas 最多 3 条。
- 根因未知时不猜；稳定规则吸收纠正动作后，只能作为有退出条件的临时提醒。
- 根因被结构性消除或达到连续正确执行条件后删除，历史由 Git 保存。
- 读取时核对：读取任何含 Gotcha 的规则文件时，每次会话首次读取顺带核对，已解决的提议删除或沉淀为规则；无证据不提议。

## 五、验证与落地

运行实例校验器，检查文件边界、重复、路由、适配器、链接、占位符和本轮 diff。

人工确认：

- `AGENTS.md` 仍是共享运行规则的唯一真实源。
- `Memory.md`、`Soul.md` 没有越界或互相重复。
- 每个 reference 都有明确且唯一的入口路由。
- 平台适配器能加载主入口，不复制共享规则。
- 没有未替换占位符、失效路径和孤立文件。
- 本轮 diff 没有覆盖对齐前的未知修改。

验证通过后，只有获得授权时才精确暂存本轮文件、检查 staged diff 并创建本地 commit。不自动 push、tag、release、部署或公开发布。

## 六、交付

报告已更新、已删除、未处理和待确认内容，以及验证、提交、入口和旧路径状态。
